= Make a product ready in English and French
:page-type: how-to
include::_fpsot-terms.adoc[]

This guide shows how to meet the main internationalization rules in a web product.
The examples use a Java message bundle, but the steps work on any platform.

== Move the text out of the code

Put every label and message in one catalog per language, as rule LOC-020 asks.
Give each message a stable key and a note for translators, as LOC-025 asks.

[source,properties]
----
# messages.properties, the English source
# Shown above the list of files. {count} is the number of files.
files.count={count, plural, one {# file} other {# files}}

# messages_fr_CA.properties
files.count={count, plural, one {# fichier} other {# fichiers}}
----

The plural form comes from the plural rules, never from a test for 1 in the code.
In French, 0 and 1 both take the singular, so "0 fichier" is correct.

== Format with locale data

Format each date, number and amount with a library that reads the link:https://cldr.unicode.org/downloads/cldr-49[data] of the {abbr-cldr-first}.
Rule LOC-010 asks for this.
Never write a pattern such as `yyyy/MM/dd` by hand.
Show the time zone next to a deadline when readers can live in other provinces.

== Choose the language

Read the choice of the person first, then the saved preference, then the `Accept-Language` header, as LOC-005 sets out.
Fall back from `fr-CA` to `fr`, then to the default of the deployment.
Put a link to the other language on every page, named "Français" or "English", with no flag.
Declare the language on the `html` element, as LOC-040 asks.

== Send the text for translation

Export the catalog as an {abbr-xliff-first} file in link:https://docs.oasis-open.org/xliff/xliff-core/v2.1/os/xliff-core-v2.1-os.html[version 2.1] for the translation team, as LOC-032 asks.
Machine translation can give a first draft, but each draft keeps the state `initial` until a person reviews it.
Import the reviewed file, and let the release checks confirm that no entry is still waiting.

[source,xml]
----
<unit id="files.count">
  <segment state="reviewed">
    <source>{count, plural, one {# file} other {# files}}</source>
    <target>{count, plural, one {# fichier} other {# fichiers}}</target>
  </segment>
</unit>
----

== Check names and addresses

Ask for the full name in one field, as LOC-050 asks.
Store each address in separate fields with its country code.
Print a Canadian postal code as `A1A 1A1`, and keep street and municipality names as written.
